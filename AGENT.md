## 3. STANDARDIZED ERROR HANDLING & MULTILINGUAL I18N (`vi` & `en`)

Backends (`.NET` and `Golang`) MUST NEVER return hardcoded, user-facing error sentences to be displayed directly on the screen, and **MUST NEVER use ABP-style colon-delimited error codes** (such as `QuickSign:Certificate:0001`). All error codes across `.NET` (`QuickSignDomainErrorCodes.cs`) and `Golang` MUST strictly use **`SCREAMING_SNAKE_CASE`**.

### 3.1. Unified Backend Error Payload (.NET & Golang)

Both `.NET` (`BusinessExceptionHandlingMiddleware`) and `Golang` (HTTP Error Responder) MUST return errors in this exact JSON structure:

```json
{
  "errorCode": "UNAUTHORIZED",
  "httpStatus": 401,
  "timestamp": "2026-11-17T07:00:00Z",
  "traceId": "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01",
  "details": {
    "limit": 5
  }
}
```

* Naming convention for `errorCode`: Uppercase letters with underscores (`SCREAMING_SNAKE_CASE`), e.g.:
  * Auth & Permission: `UNAUTHORIZED`, `FORBIDDEN_ACCESS`, `INVALID_CREDENTIALS`, `REGISTRATION_FAILED`, `SESSION_EXPIRED`, `API_KEY_INVALID`, `API_KEY_REVOKED`, `API_KEY_SCOPE_INSUFFICIENT`.
  * Certificates: `CERT_NOT_FOUND`, `MAX_ACTIVE_CERTS_REACHED`, `CERT_ALREADY_REVOKED`, `INVALID_REVOCATION_TIMESTAMP`, `UNAUTHORIZED_CERT_ACCESS`.
  * Signing & Verification: `INVALID_PDF_FORMAT`, `SIGNING_FAILED`, `TAMPERED_CONTENT`, `CERT_REVOKED_AT_SIGNING`, `CERT_EXPIRED_AT_SIGNING`, `UNKNOWN_SIGNATURE`, `CODE_EXISTS_UNVERIFIED_CONTENT`.
  * System: `RATE_LIMIT_EXCEEDED`, `INTERNAL_SERVER_ERROR`, `SERVICE_UNAVAILABLE`.

## 4. UI/UX, MINIMALIST DESIGN & SECURITY ILLUSION PREVENTION (NEXT.JS)

### 4.1. Minimalist Aesthetic (Minimal Design)
* **Visual Clarity**: Prioritize whitespace, clean typography, subtle borders, and high-contrast readability. Avoid visual clutter, unnecessary decorative gradients, or overwhelming data tables.
* **Progressive Disclosure**: Show only essential information upfront (e.g., Document Status: Valid / Modified, Signer Name, Signing Date). Place technical metadata ($\text{SHA-256}$ hashes, X.509 serial numbers, PEM blocks) inside collapsible "View Details" drawers or copyable badges.

### 4.2. Preventing QR Code "Security Illusion"
* When a user scans a QR code and queries `GET /api/v1/verify/code/{document_code}`, the system only proves that the code exists in the database—not that the physical printout or local PDF file in their hands is unaltered.
* When the API returns `CODE_EXISTS_UNVERIFIED_CONTENT`, the Next.js UI MUST render a prominent **Warning Banner** explaining that while the document ID is genuine, the user must upload the original digital file (PDF/JSON) to cryptographically verify that its content has not been tampered with.

### 4.4. Natural, Human-Centric Language (Anti-Jargon)

## 5. BACKEND PERFORMANCE, CRYPTOGRAPHIC SAFETY & CONCURRENCY RULES

Both `.NET` (`src/management`) and `Golang` (`src/crypto-engine`) services must be engineered for maximum throughput, low latency, and cryptographic memory safety.

### 5.1. Offload Heavy or Non-Blocking Tasks to Background Workers

Any operation that does not strictly need to block the immediate HTTP/gRPC response MUST be offloaded to an asynchronous background queue:

1. **In `Golang Crypto Engine` (`src/crypto-engine`)**:
   * Use bounded **Worker Pools with Buffered Channels** (`chan VerificationEvent`, `chan AuditTask`) and graceful shutdown (`context.Context` + `sync.WaitGroup`).
   * **What to offload**: Recording `verification_logs` into PostgreSQL, incrementing verification counters, updating `api_keys.last_used_at`, and writing optional PDF copies to local disk. The `/verify` and `/sign` endpoints must return the cryptographic result immediately.
   * **Mandatory Atomic SQL Counter Updates**: Background workers MUST NEVER perform read-modify-write in Go memory when updating counters on `signed_documents`. Always execute atomic SQL updates in PostgreSQL via `pgx`:
     ```sql
     UPDATE signed_documents
     SET total_verify_count = total_verify_count + 1,
         unique_verify_count = unique_verify_count + $1,
         tampered_alert_count = tampered_alert_count + $2,
         last_verified_at = $3
     WHERE id = $4;
     ```

2. **In `.NET Management Service` (`src/management`)**:
   * Use `System.Threading.Channels.Channel<T>` combined with `BackgroundService` (`IHostedService`) registered in `QuickSign.Infrastructure`.
   * **What to offload**: Cache warming/invalidation batches across Redis, aggregating dashboard statistics snapshots, and periodic cleanup of expired certificates/API keys.

### 5.2. Cryptographic Integrity, Memory Safety & JWT Resilience (`Golang`)
* **Compliant PAdES Signing (ISO 32000-1 / ETSI EN 319 142)**: Never inject arbitrary dictionary keys outside a valid PDF Incremental Update, as it corrupts the cross-reference (`xref`) table in Adobe Acrobat/Foxit Reader. Always embed `document_code` inside the **Signed Attributes (Authenticated Attributes)** of the PKCS#7/CMS detached signature blob so it is cryptographically bound to the document digest.
* **Deep Cryptographic Memory Zeroing**: Beyond zeroing raw PEM/DER byte buffers (`memguard.ZeroBytes`), always invoke `memguard.ZeroPrivateKey(privKey)` via `defer` to explicitly zero out the underlying `big.Int` word slices (`D`, `Primes`, `Precomputed` values on `*rsa.PrivateKey`; `D` on `*ecdsa.PrivateKey`) on the Go heap before releasing the pointer.
* **Flexible JWT Role Parsing (`FlexibleRoleClaim`)**: QuickBite Identity JWTs may serialize the `role` claim as either a single JSON `string` or a `[]string` array. Always parse `role` claims using a custom `FlexibleRoleClaim` type implementing `json.Unmarshaler` so single-role and multi-role tokens never cause JSON unmarshal failures or panics.
* **Zero-Allocation Streaming**: Stream PDF files directly (`io.Reader` / `io.Writer`) when computing $\text{SHA-256}$ digests. Never load multiple copies of large PDF files into RAM simultaneously.

### 5.3. EF Core Read Optimization & Caching (`.NET`)
* Always use `.AsNoTracking()` on all read-only queries (`GetMyCertificatesAsync`, `GetDocumentsAsync`, `StatisticsAppService`).
* Use AutoMapper `.ProjectTo<TDto>(_mapper.ConfigurationProvider)` for list and analytics queries so SQL `SELECT` only fetches required columns.
* Validate `X-API-Key` and fetch active `PublicKeyPem` via Redis first (`O(1)` lookup); only query PostgreSQL on cache miss.
